## 문제

통역 파이프라인 4단계는 관용구 사전으로 처리하지 못한 문장을 LLM으로 번역해야 한다. 최초 요구사항은 Claude API(`claude-sonnet-5`)를 모델명까지 하드코딩하는 것이었다.

그러나 현재 팀은 Anthropic API 비용을 집행할 수 없다. Claude Pro 구독은 claude.ai와 Claude Code 사용에만 해당하고 API 크레딧을 포함하지 않아, 구독 여부와 무관하게 API 호출이 불가능하다.

동시에 이 제약이 영구적이지 않다. 팀 크레딧이 생기거나 예산이 확보되면 Claude로 돌아갈 수 있어야 한다.

## 결정

번역을 `Translator` 인터페이스 뒤에 두고 provider 구현체를 교체 가능하게 한다. 첫 구현은 Gemini 무료 티어를 사용한다.

파이프라인의 나머지 요소는 provider를 알지 못한다.

- 관용구 사전 매칭과 확정 번역 사전 조립
- 시스템 프롬프트 본문 생성
- 최근 3~5턴 대화 컨텍스트 버퍼
- 출력 JSON 조립과 `used_glossary` 판정

provider마다 달라지는 것은 SDK 호출, 응답에서 텍스트를 꺼내는 방식, 시스템 프롬프트를 넣는 자리, 예외 타입뿐이다.

## 대안

| 대안 | 검토 결과 |
| --- | --- |
| Claude API 유료 사용 | 비용 집행 불가로 현재 선택할 수 없다. |
| Gemini로 완전 교체 (추상화 없음) | 코드가 단순해지지만 Claude 전환 시 해당 모듈을 다시 쓴다. provider 차이가 호출부에 한정되므로 추상화 비용이 작아 이득이 크지 않다. |
| 로컬 모델 (Ollama 등) | 비용은 없지만 소형 모델의 한국어-베트남어 뉘앙스 번역 품질이 이 기능의 요구사항을 만족하는지 검증되지 않았다. |
| Kiro 등 에이전틱 IDE | 에디터 도구이고 런타임에 호출할 추론 엔드포인트를 제공하지 않는다. 번역 백엔드로 쓸 수 없다. |

## 결정 이유

- provider별 차이가 작아 추상화 비용이 낮다. 나머지 로직은 그대로 공유된다.
- 크레딧이 생기면 구현체 하나를 추가해 전환할 수 있고, 파이프라인 코드는 바뀌지 않는다.
- 테스트에 `FakeTranslator`를 끼우면 API 키 없이 5단계 엔드투엔드 검증이 가능하다. 지금처럼 키를 쓸 수 없는 상황에서 실질적인 이점이다.
- `docs/STRUCTURE.md`가 `apps/server/src/integrations/llm`을 교체 가능한 외부 서비스 자리로 이미 정의하고 있어, 이후 Server 이식 시 구조가 그대로 이어진다.

## 영향

- `apps/translation-pipeline/.env.example`에 `GEMINI_API_KEY`를 추가했다. 사용할 provider의 키만 채우면 된다.
- 모델명 하드코딩 요구는 더 이상 유효하지 않다. 모델명은 각 provider 구현체 안의 상수로 둔다.
- 1·3단계는 provider와 무관하므로 이 결정의 영향을 받지 않는다.

### 데이터 취급 제약

Gemini 무료 티어는 일반적으로 입력 데이터를 모델 개선에 사용한다. 이 제품은 회의 발화를 다루므로 다음 제약을 둔다.

- 무료 티어는 개발과 데모 검증에만 사용한다.
- 실제 사용자 회의 내용에는 적용하지 않는다.
- 실사용 전에 유료 티어 또는 입력을 학습에 사용하지 않는 provider로 전환한다.

`docs/CONVENTIONS.md`의 민감 정보 규칙과 `AGENTS.md`의 회의 녹취 취급 규칙을 따른다.

## 재검토 조건

- 팀 API 크레딧이 확보된 경우
- Gemini 무료 티어의 응답 품질이나 요청 한도가 회의 통역 요구를 만족하지 못하는 경우
- 실사용 배포를 준비하는 시점
