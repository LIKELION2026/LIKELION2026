## 1. 제품 개요

### 한 줄 소개

서로 다른 국가의 팀원이 같은 공간에서 일하는 감각을 갖고, 언어와 시차 때문에 사라지는 업무 맥락을 실시간으로 이어 가도록 돕는 AI 협업 가상 오피스다.

### 제품 목표

- 원격 팀원이 동료의 업무 가능 상태와 협업 맥락을 부담 없이 파악하게 한다.
- 화상회의에서 말한 내용을 상대 언어 자막으로 빠르게 이해하게 한다.
- AI가 활동 기록을 바탕으로 사용자가 확인·수정할 수 있는 상태와 업무 요약 초안을 만든다.
- 업무 외 짧은 상호작용을 통해 팀원 사이의 심리적 거리를 줄인다.

### MVP 원칙

- 팀원의 근무를 감시하거나 생산성을 점수화하지 않는다.
- 상태와 요약은 AI의 추정값일 수 있으므로 근거와 수정 수단을 제공한다.
- 외부 도구 연동은 최소화한다. 데모에서는 가상 오피스, 화상회의, 수동 입력 또는 Mock 이벤트를 우선 구현한다.
- 실시간 번역은 회의에서 실제로 확인 가능한 사용자 가치로 검증한다.

## 2. 문제 정의

### 핵심 문제

서로 다른 장소와 언어로 협업하는 팀은 동료가 지금 어떤 업무 맥락에 있는지, 질문해도 되는지, 회의에서 어떤 결정이 내려졌는지를 즉시 알기 어렵다. 업무 지연의 이유를 추측하게 되고, 확인과 재설명이 반복되며 신뢰와 협업 속도가 함께 떨어진다.

### 해결해야 할 문제

| 문제 | 현재 발생하는 상황 | 결과 |
| --- | --- | --- |
| 업무 맥락 부재 | 같은 공간에 있지 않아 동료의 협업 가능 상태, 진행 중인 작업, 다음 행동을 알기 어렵다. | 질문을 미루거나 불필요하게 재확인한다. |
| 언어 장벽 | 화상회의에서 발언을 바로 이해하지 못하거나, 번역 과정에서 중요한 맥락이 늦게 전달된다. | 의사결정이 늦어지고 오해가 생긴다. |
| 비동기 맥락 공백 | 시차 또는 부재 시간에 요청·결정·논의가 여러 채널에 흩어진다. 팀원이 다시 확인할 때는 요청 배경과 최신 결정 맥락을 빠르게 파악하기 어렵다. | 응답 전에 맥락을 찾거나 같은 내용을 다시 질문하게 된다. |
| 관계 형성 부족 | 짧은 대화와 자연스러운 접점이 적어 서로의 성향·역할을 알 기회가 부족하다. | 도움 요청과 피드백의 심리적 장벽이 높아진다. |

### 문제정의 검증 가설

- 팀원은 '온라인' 여부보다 지금 질문 가능한지와 무엇을 진행 중인지 알고 싶어 한다.
- 번역된 회의 자막이 있으면 회의 참여와 결정 이해도가 높아진다.
- 활동 기록을 사람이 직접 길게 작성하기보다 AI 초안을 검토·수정하는 방식이 부담을 낮춘다.
- 가벼운 아이스브레이킹은 업무 공간에 자연스럽게 녹아들 때 참여 가능성이 높다.

## 3. 타겟 사용자와 시나리오

### 1차 타겟

한국 팀과 해외 파트너·팀원이 함께 프로젝트를 수행하며, 화상회의와 비동기 메시지를 병행하는 소규모 협업팀.

해커톤 데모에서는 한국 측 운영·기획팀과 해외 개발·운영 파트너가 공동 프로젝트를 진행하는 상황을 가정한다. 실제 특정 조직의 운영 방식으로 단정하지 않으며, 인터뷰 결과에 따라 역할과 세부 시나리오는 조정한다.

### 대표 사용자

| 사용자 | 목표 | 어려움 |
| --- | --- | --- |
| 한국 측 PM 또는 운영 담당자 | 해외 팀과 업무를 빠르게 맞추고 다음 행동을 정한다. | 상대 팀의 진행 맥락과 회의 결정사항을 다시 확인해야 한다. |
| 해외 개발·운영 담당자 | 요청의 우선순위와 의도를 정확히 이해하고 진행 상황을 공유한다. | 언어 차이와 시차 때문에 즉시 질문하거나 피드백을 받기 어렵다. |
| 디자인·프론트엔드 협업 담당자 | 변경사항을 공유하고 빠르게 피드백을 받는다. | 문서·메신저·회의에 정보가 흩어져 있다. |

### 데모 사용자 시나리오

1. 한국 측 PM이 가상 오피스에 입장해 자신의 오늘 일정과 집중 업무를 확인한다.
2. 해외 개발 담당자의 아바타에서 '집중 작업 중, 30분 후 응답 가능' 상태와 연결된 작업 맥락을 확인한다.
3. PM이 아바타 근처에서 텍스트 메시지를 보내거나 화상회의를 시작한다.
4. 회의 발언이 각 참여자에게 상대 언어의 실시간 자막으로 표시된다.
5. 회의가 끝나면 AI가 결정사항, 미해결 항목, 담당자, 다음 행동을 초안으로 만들고 참석자가 수정·확정한다.
6. 확정된 요약은 부재 중이던 팀원이 다시 접속했을 때 브리핑 피드에서 확인한다.

## 4. 핵심 기능

### F1. 가상 오피스와 협업 가능 상태

**사용자 가치:** 상대에게 질문하거나 회의를 제안해도 되는 시점과 진행 중인 업무의 맥락을 빠르게 파악한다.

| 항목 | MVP 정의 |
| --- | --- |
| 가상 오피스 | Phaser 기반 2D 공간에서 팀원 아바타와 좌석·회의실을 표시한다. |
| 상태 | `협업 가능`, `집중 작업`, `회의 중`, `자리 비움`을 제공한다. |
| 상태 근거 | 사용자가 직접 선택하거나 캘린더·회의 참여·작업 타이머 이벤트를 바탕으로 AI가 초안을 제안한다. |
| 작업 맥락 | 사용자가 공개한 한 줄 작업 목표와 다음 응답 가능 시간을 아바타 정보에서 표시한다. |
| 상호작용 | 근처 아바타 선택 후 텍스트 메시지 또는 회의 요청을 보낸다. |

**완료 기준**

- 두 명 이상이 같은 오피스에 접속해 서로의 상태 변화를 실시간으로 본다.
- 상태 변경은 Socket 이벤트로 다른 참여자에게 반영된다.
- AI 제안 상태는 사용자가 확인 또는 수정한 뒤에만 공유된다.

### F2. 화상회의와 실시간 번역 자막

**사용자 가치:** 발언 언어가 달라도 회의 흐름과 결정을 놓치지 않는다.

| 항목 | MVP 정의 |
| --- | --- |
| 회의 시작 | 회의실 또는 팀원 메뉴에서 LiveKit 기반 회의방에 입장한다. |
| 음성 인식 | 발화 음성을 텍스트로 변환한다. 데모 안정성을 위해 사전 준비된 음성·자막 fallback을 허용한다. |
| 번역 자막 | 원문과 사용자가 선택한 언어의 번역문을 함께 표시한다. |
| 언어 범위 | 한국어와 영어를 우선 지원한다. 다른 언어는 확장 가능성으로만 제시한다. |
| 오류 처리 | 인식·번역 지연 또는 실패 시 원문, 처리 중 상태, 재시도 안내를 표시한다. |

**완료 기준**

- 참여자별 자막 언어를 선택할 수 있다.
- 발언자, 원문, 번역문, 시각을 포함한 자막 이벤트가 회의 화면에 표시된다.
- 번역 결과가 단정적이지 않을 수 있음을 UI에서 인지할 수 있다.

### F3. AI 회의 정리와 업무 브리핑

**사용자 가치:** 회의와 대화에 없었던 팀원도 결정의 맥락과 다음 행동을 빠르게 파악한다.

| 항목 | MVP 정의 |
| --- | --- |
| 입력 | 회의 자막, 사용자가 작성한 작업 목표, 상태 변경 이벤트 |
| AI 출력 | 결정사항, 미해결 항목, 담당자, 다음 행동, 확인이 필요한 누락 항목 |
| 검토 | 사용자가 항목을 수정·삭제·확정한다. |
| 공유 | 확정한 브리핑을 팀 오피스의 공용 피드에서 확인한다. |
| 제한 | AI가 입력에 없는 담당자·기한·결정을 사실처럼 만들지 않는다. 불확실한 내용은 질문 또는 `확인 필요`로 표시한다. |

**완료 기준**

- 회의 종료 후 구조화된 요약 초안을 생성한다.
- 사용자가 편집한 결과만 팀 공용 피드에 게시된다.
- 각 요약 항목에 입력 자막 또는 사용자 입력의 근거를 연결할 수 있다.

### F4. 팀 아이스브레이킹

**사용자 가치:** 업무 외 가벼운 상호작용으로 서로를 알아갈 기회를 만든다.

| 항목 | MVP 정의 |
| --- | --- |
| 진입 | 오피스 내 공용 공간 또는 휴식 공간에서 참여한다. |
| 콘텐츠 | 오늘의 질문 카드 또는 짧은 협동형 미니 활동 중 하나를 제공한다. |
| 언어 지원 | 질문과 답변에 번역 보기를 제공한다. |
| 범위 제한 | 점수 경쟁, 공개 랭킹, 과도한 프로필 수집은 MVP에서 제외한다. |

## 5. AI 기능 명세

### AI가 해결하는 일

| 기능 | 입력 | 출력 | 사용자 통제 |
| --- | --- | --- |
| 상태 초안 | 캘린더·회의·작업 이벤트, 사용자 설정 | 제안 상태와 예상 응답 가능 시간 | 수정·거절 후에만 공유 |
| 번역 자막 | 음성 인식 원문, 발화 언어, 대상 언어 | 원문과 번역 자막 | 언어 선택, 원문 보기 |
| 회의 요약 | 자막·결정 태그·사용자 메모 | 결정, 이슈, 담당, 다음 행동, 확인 질문 | 편집·삭제·확정 |
| 맥락 누락 점검 | 확정 전 브리핑 | 담당자·기한·근거 누락 경고 | 경고 무시 또는 보완 |

### AI 품질 원칙

- 번역과 요약의 근거 데이터를 사용자에게 보여 준다.
- 자동 게시, 자동 업무 배정, 근거 없는 근무 상태 판정은 하지 않는다.
- 응답 지연 시 기본 상태와 수동 입력 흐름이 계속 동작해야 한다.
- 음성·회의 데이터 보관 기간과 열람 권한은 구현 전 정책으로 확정한다.

## 6. 정보 구조와 핵심 화면

```text
입장 / 팀 선택
  -> 가상 오피스
       -> 팀원 상태 및 작업 맥락
       -> 1:1 메시지 / 회의 요청
       -> 회의실
            -> 화상회의
            -> 실시간 원문·번역 자막
            -> 회의 종료
                 -> AI 브리핑 검토·확정
  -> 브리핑 피드
  -> 아이스브레이킹 공간
```

### 필수 화면

1. 팀 입장 및 사용자 언어 선택
2. 가상 오피스와 팀원 상태
3. 팀원 상세 정보 및 메시지·회의 요청 메뉴
4. 화상회의와 실시간 번역 자막
5. AI 브리핑 편집·확정 화면
6. 팀 브리핑 피드
7. 아이스브레이킹 공간 또는 질문 카드

## 7. MVP 범위와 우선순위

### P0 - 데모 필수

- 사용자 입장과 언어 설정
- 다중 사용자 가상 오피스 및 실시간 상태 동기화
- 1:1 또는 소규모 화상회의 입장
- 한국어·영어 실시간 번역 자막
- 회의 종료 후 AI 브리핑 생성, 수정, 확정
- 확정 브리핑 피드 확인

### P1 - 시간 여유 시

- 캘린더 이벤트를 활용한 상태 초안
- 메시지 알림과 응답 가능 시간 표시
- 브리핑 누락 점검
- 아이스브레이킹 질문 카드와 번역 보기

### P2 - 해커톤 이후 검토

- GitHub, Jira, Figma 등 외부 업무 도구 연동
- 시간대·부재 상태를 고려한 브리핑 알림 및 개인화 요약
- 다국어 확장과 용어 사전
- 회의 검색, 장기 프로젝트 맥락 관리

### MVP에서 제외

- 근무 시간 추적, 활동량 기반 평가, 감시 목적의 화면·카메라 수집
- AI가 사용자 승인 없이 상태·업무·회의 요약을 외부에 게시하는 기능
- 여러 외부 서비스의 완전한 양방향 연동

## 8. 기술 방향

| 영역 | 선택 | 역할 |
| --- | --- | --- |
| Client | React, TypeScript, Phaser | 가상 오피스, 상태 UI, 브리핑 화면 |
| Server | NestJS, Socket | 인증, 도메인 API, 실시간 상태·자막 이벤트 |
| Shared | TypeScript 패키지 | DTO, 도메인 타입, Socket 이벤트 계약 |
| 화상회의 | LiveKit | 방 생성, 참가자 연결, 오디오·비디오 스트림 |
| AI | LLM 및 음성 인식·번역 API | 자막 변환·번역, 회의 브리핑, 누락 점검 |
| 데이터 | 구현 단계에서 선택 | 사용자, 팀, 상태, 회의, 확정 브리핑 저장 |

### 실시간 이벤트 초안

```text
presence.updated
member.status.updated
meeting.requested
meeting.joined
subtitle.created
briefing.drafted
briefing.confirmed
```

이벤트의 실제 DTO와 권한 규칙은 구현 전 `packages/shared`와 ADR에서 확정한다.

## 9. 성공 기준

### 데모 성공 기준

- 한국어 사용자와 영어 사용자 역할이 하나의 오피스에서 서로의 협업 가능 상태를 확인한다.
- 한 명의 발언이 상대 언어 자막으로 표시된다.
- 회의 종료 후 AI 초안이 생성되고 사용자가 수정·확정한다.
- 확정된 결정사항과 다음 행동을 다음 참여자가 브리핑 피드에서 이해할 수 있다.

### 사용자 검증 질문

- 상태와 작업 맥락이 실제로 질문·회의 요청 타이밍을 판단하는 데 도움이 되었는가?
- 번역 자막이 회의 이해와 발언 참여에 도움이 되었는가?
- AI 브리핑에서 수정이 필요했던 내용은 무엇이며, 근거를 확인할 수 있었는가?
- 가상 오피스와 아이스브레이킹이 팀원 간 대화를 시작하는 데 도움이 되었는가?

## 10. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 실시간 음성 인식·번역 지연 | 자막 처리 상태와 원문을 우선 표시하고, 데모용 fallback 흐름을 준비한다. |
| AI가 잘못된 결론을 요약 | 자동 확정을 금지하고, 근거·편집·확정 단계를 제공한다. |
| 상태 표시가 감시로 느껴짐 | 상태는 사용자 제어를 기본으로 하고, 생산성 점수·활동 감시는 제외한다. |
| 외부 연동 구현 범위 과다 | P0는 Mock 이벤트와 수동 입력으로 완성하고, 실제 연동은 P1 이후로 둔다. |
| 가상 오피스가 장식에 그침 | 상태 확인, 메시지, 회의 진입, 브리핑 피드라는 핵심 행동이 공간 안에서 이어지게 설계한다. |

## 11. 오픈 질문

- 실제 타겟 조직이 가장 자주 사용하는 언어 조합과 회의 방식은 무엇인가?
- 어떤 상태 정보까지 공개하는 것을 편안하게 느끼는가?
- 회의 데이터의 보관 기간, 접근 권한, 삭제 요청은 어떻게 정의할 것인가?
- AI 브리핑의 담당자·마감일을 어떤 입력 또는 확인 절차로 신뢰할 수 있게 할 것인가?
- 아이스브레이킹은 질문 카드와 협동형 미니 활동 중 어느 방식이 실제 참여에 더 적합한가?
