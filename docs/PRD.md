## 1. 제품 개요

### 한 줄 소개

한국과 베트남처럼 서로 다른 곳에서 일하는 팀이, 감시 없이 오늘의 업무·부재 일정·대화 진입점을 공유하고 언어 장벽을 낮추도록 돕는 AI 협업 가상 오피스다.

### 제품 컨셉

- 하나의 Global Office 안에서 팀원의 존재, 협업 가능 상태, 오늘의 작업, 중요한 부재 일정을 확인한다.
- 큰 가상 오피스에서도 피플 목록으로 팀원을 찾아가거나, 호출 요청과 메시지로 빠르게 대화를 시작한다.
- 회의실에서는 화상회의와 한국어·베트남어 실시간 번역 자막으로 즉시 소통한다.
- AI는 업무 상태를 감시·판정하지 않고, 사용자가 확인하는 TODO 초안·일정 충돌 알림·회의 번역과 정리를 보조한다.

### 참고 원칙

공간 탐색, 피플 목록, 아바타 상호작용은 ZEP의 사용 흐름을 참고한다. 다만 기능과 시각 디자인을 복제하지 않고, 글로벌 업무 협업 문제에 맞게 재구성한다.

## 2. 문제 정의

한국 팀과 베트남 팀이 원격으로 함께 일할 때, 팀원은 상대가 실제로 어떤 작업을 진행하는지, 언제 자리를 비우는지, 큰 가상 공간에서 어떻게 바로 대화를 시작하는지 알기 어렵다. 이 불확실성은 업무 지연을 개인의 태도로 오해하게 만들고, 일정과 신뢰를 함께 흔든다.

| 문제 | 실제 상황 | 결과 |
| --- | --- | --- |
| 업무 진행 맥락의 불확실성 | 화면 공유나 감시 없이 상대가 오늘 어떤 일을 진행하는지 알기 어렵다. | 지연 이유를 추측하고 불필요한 오해가 생긴다. |
| 중요 일정의 가시성 부족 | 휴가, 재택, 회의 등 협업에 영향을 주는 일정을 제때 알지 못한다. | 의존 작업의 계획이 틀어지고 일정 공백이 발생한다. |
| 큰 공간에서의 팀원 탐색 비용 | 접속자는 많고 맵은 넓지만, 특정 팀원에게 즉시 접근할 방법이 부족하다. | 질문·회의 요청이 늦어지고 공간이 장식처럼 남는다. |
| 언어 장벽 | 화상회의 중 상대 언어 발화를 바로 이해하기 어렵다. | 의사결정과 피드백이 늦어지며 맥락이 손실된다. |

### 해결 원칙

- 화면 공유, 키보드·마우스 추적, 활동량 점수, 근무 감시는 제공하지 않는다.
- TODO와 일정은 팀원이 직접 작성·수정하고 공개 범위를 선택하는 정보다.
- `찾아가기`는 내 아바타 또는 카메라를 이동시키는 기능이며, `불러오기`는 상대가 수락할 수 있는 호출 요청이다. 강제 이동은 하지 않는다.
- AI 결과는 자동 공개하지 않는다. 사용자가 검토·수정·확정한 후에만 팀에 공유한다.

## 3. 타겟 사용자와 데모 시나리오

### 1차 타겟

한국과 베트남에 나뉘어 있는 소규모 프로젝트 팀. 기획·운영·디자인·개발 역할이 함께 일하며, 비동기 메시지와 화상회의를 병행한다.

해커톤 데모는 한국 측 PM과 베트남 측 개발 담당자가 같은 프로젝트를 진행하는 상황을 기준으로 한다. 실제 조직의 운영 방식으로 단정하지 않고, 인터뷰에서 확인한 문제를 검증하는 시나리오로 사용한다.

### 대표 시나리오

1. 한국 측 PM은 마감이 가까운 API 작업을 계획한다.
2. PM은 피플 목록에서 베트남 개발 담당자를 찾고, 프로필 또는 데스크의 `오늘의 작업`에서 진행 중인 TODO와 blocker를 확인한다.
3. 공유 캘린더에서 담당자가 이틀 후 휴가임을 확인하고, 의존 작업의 회의 시점을 앞당긴다.
4. PM은 `찾아가기`로 해당 팀원 위치로 이동하거나 `불러오기`를 보낸다. 담당자는 요청을 수락한 뒤 회의실로 이동한다.
5. 회의에서는 한국어와 베트남어 원문·번역 자막을 확인하며 합의한다.
6. 회의 후 각 사용자는 합의된 다음 작업을 자신의 TODO에 반영한다. AI 요약은 시간 여유가 있을 때 초안으로 제공하고 사용자가 확정한다.

## 4. 핵심 기능

### F1. Global Office와 팀원 상태

**사용자 가치:** 같은 프로젝트에 누가 연결돼 있고 지금 대화 가능한지 빠르게 파악한다.

| 항목 | MVP 정의 |
| --- | --- |
| 공간 | 하나의 Global Office 안에 Korea Team Zone, Vietnam Team Zone, Shared Collaboration Zone, Meeting Room을 둔다. |
| 상태 | `협업 가능`, `집중 작업`, `회의 중`, `자리 비움`을 사용자가 직접 선택한다. |
| 상태 라벨 | 아바타에 이름과 상태를 표시한다. 색상 외 아이콘 또는 텍스트를 함께 쓴다. |
| 상호작용 | 아바타·데스크를 선택하면 팀원 요약과 TODO 보기, 메시지, 찾아가기, 불러오기 메뉴를 연다. |

### F2. 오늘의 작업 TODO

**사용자 가치:** 상대를 감시하지 않고도 오늘 무엇을 진행하는지와 도움이 필요한 지점을 파악한다.

| 항목 | MVP 정의 |
| --- | --- |
| 작성 | 사용자가 오늘의 TODO를 직접 추가하고 `예정`, `진행 중`, `완료`, `막힘` 상태를 선택한다. |
| 열람 | 다른 팀원이 데스크를 클릭하거나 아바타 프로필의 `오늘의 작업 보기`에서 공개 TODO를 본다. |
| 공개 범위 | 기본값은 작업 제목·상태·blocker 여부만 공유한다. 세부 메모는 작성자가 선택적으로 공개한다. |
| 신뢰 기준 | TODO는 업무 진행의 증명이나 평가 지표가 아니다. 활동량·화면·시간을 수집하지 않는다. |
| AI 보조 (P1) | 회의에서 확정한 다음 행동이나 사용자가 입력한 작업을 바탕으로 TODO 초안을 제안하고, 사용자가 확인한 뒤 저장한다. |

### F3. 공유 캘린더와 협업 가능 일정

**사용자 가치:** 휴가·재택·장기 회의처럼 협업 계획에 영향을 주는 공백을 미리 알고 일정을 조정한다.

| 항목 | MVP 정의 |
| --- | --- |
| 일정 종류 | 휴가, 재택, 부재, 회의, 집중 작업 시간을 등록한다. |
| 보기 | 팀 공용 주간 캘린더에서 팀원의 중요한 일정과 겹침을 확인한다. |
| 표시 | 사람 목록과 아바타 프로필에는 현재·가까운 부재 정보만 짧게 보여 준다. |
| 공개 범위 | 개인 사유·세부 위치는 수집하지 않는다. 협업 가능 여부에 필요한 범위만 공유한다. |
| AI 보조 (P1) | 사용자가 지정한 마감과 팀원의 공개 부재 기간이 겹칠 때 확인용 경고를 제안한다. |

### F4. 피플 목록과 빠른 접근

**사용자 가치:** 넓은 맵에서도 원하는 팀원을 찾고, 공간 이동과 대화를 빠르게 시작한다.

| 항목 | MVP 정의 |
| --- | --- |
| 피플 목록 | 현재 접속한 사람, 상태, 현재·가까운 부재 정보를 좌측 패널에서 표시한다. |
| 검색 | 이름 또는 역할로 팀원을 검색한다. |
| 프로필 보기 | 아바타, 역할, 상태, 오늘의 공개 TODO, 가까운 중요 일정을 보여 준다. |
| 찾아가기 | 내 아바타 또는 카메라를 선택한 팀원의 위치로 이동한다. |
| 불러오기 | 상대에게 회의실 또는 내 위치로의 호출 요청을 보낸다. 상대가 수락할 때만 이동한다. |
| 메시지 보내기 | 1:1 메시지 작성 진입점을 제공한다. P0에서는 UI·요청 흐름과 Mock 응답까지 검증할 수 있다. |

### F5. 화상회의와 실시간 번역 자막

**사용자 가치:** 회의에서 한국어와 베트남어 발화를 이해하고 즉시 피드백한다.

| 항목 | MVP 정의 |
| --- | --- |
| 회의 입장 | Meeting Room 구역에 들어가면 별도 페이지 이동 없이 오피스 화면 안에서 LiveKit 회의 연결을 시작한다. 호출 요청은 후속 단계에서 같은 인게임 회의 흐름으로 연결한다. |
| 번역 자막 | 발화자, 원문, 대상 언어 번역문, 처리 상태를 함께 표시한다. |
| 언어 범위 | 한국어와 베트남어를 우선 지원한다. |
| 오류 처리 | 인식·번역 지연 시 원문과 처리 중 상태를 우선 보여 준다. |
| 회의 요약 (P1) | 자막을 바탕으로 다음 행동 초안을 만들되, 사용자 편집·확정 후에만 공유한다. |

## 5. AI 활용 원칙

| 기능 | 입력 | 출력 | 사용자 통제 |
| --- | --- | --- | --- |
| TODO 초안 | 사용자가 선택한 회의 다음 행동, 수동 입력 | TODO 제목·상태 초안 | 수정·거절·저장 선택 |
| 일정 충돌 알림 | 공개 부재 일정, 사용자가 지정한 마감 | 확인이 필요한 일정 겹침 경고 | 무시 또는 조정 |
| 번역 자막 | 음성 인식 원문, 발화·대상 언어 | 원문과 번역 자막 | 언어 선택, 원문 보기 |
| 회의 요약 | 자막, 사용자 메모 | 결정·다음 행동 초안 | 편집·삭제·확정 |

- AI는 업무 수행 여부나 생산성을 평가하지 않는다.
- AI는 사용자가 공개하지 않은 화면, 활동 로그, 개인 캘린더를 입력으로 사용하지 않는다.
- AI가 불확실한 담당자·기한을 만들면 `확인 필요`로 표시한다.

## 6. 정보 구조와 필수 화면

```text
입장 / UI 언어 선택
  -> Global Office
       -> 피플 목록
            -> 검색
            -> 프로필 / 오늘의 작업
            -> 찾아가기 / 불러오기 / 메시지
       -> 공유 캘린더
       -> 데스크·아바타 상호작용
       -> Meeting Room
            -> 화상회의
            -> 원문·번역 자막
```

입장 화면의 UI 언어는 한국어와 베트남어를 우선 지원하며, 사용자는 입장 전과 입장 후 HUD 설정에서 변경할 수 있다. UI 언어는 국가, 참가자 말하기 언어, 회의 AI 번역 대상 언어와 분리해 저장한다.

### P0 필수 화면

1. Global Office와 팀별 Zone
2. 피플 목록, 검색, 프로필 액션 메뉴
3. 팀원 TODO 보기와 내 TODO 편집
4. 팀 공용 주간 캘린더
5. 회의실 구역 진입과 인게임 Meeting 오버레이
6. 화상회의의 원문·번역 자막 상태
7. 한국어·베트남어 UI 언어 선택과 입장 후 변경
8. 연결 중, 빈 상태, 요청 대기·거절, 오류 상태

## 7. MVP 범위와 우선순위

### P0 - 해커톤 데모 필수

- 다중 사용자 Global Office, 아바타 상태·위치 동기화
- 피플 목록, 검색, 프로필, 찾아가기 UI
- 수동 작성 TODO와 아바타·데스크 기반 TODO 열람
- 수동 등록 공유 캘린더와 휴가·재택·부재 표시
- Meeting Room 입장과 LiveKit 회의 연결
- 한국어·베트남어 실시간 번역 자막 또는 안정적인 데모 fallback
- 한국어·베트남어 시스템 UI와 새로고침 후 유지되는 UI 언어 설정

### P1 - 시간 여유 시

- 호출 요청 수락 후 회의실 이동
- 실제 1:1 메시지 저장·알림
- TODO 초안과 일정 충돌 경고
- 회의 요약 편집·확정
- 시차에 따른 Team Zone 조명과 근무 상태 연출

### MVP에서 제외

- 화면 공유 강제, 카메라·키보드·마우스 감시, 활동량 기반 평가
- 강제 아바타 이동 또는 사용자의 동의 없는 회의 참가
- 휴가 사유, 세부 위치, 개인 캘린더 전체 수집
- GitHub·Jira·Figma의 완전한 양방향 연동

## 8. 기술 방향

| 영역 | 선택 | 역할 |
| --- | --- | --- |
| Client | React, TypeScript, Phaser | 오피스, 피플 목록, TODO·캘린더 UI |
| Server | NestJS, Socket.IO | Presence, TODO·일정·호출 요청 API와 실시간 이벤트 |
| Shared | TypeScript 패키지 | 도메인 타입, DTO, Socket 이벤트 계약 |
| 화상회의 | LiveKit | 회의방, 오디오·비디오 스트림 |
| 통역 | STT·번역 파이프라인 | 한국어·베트남어 자막 생성 |
| AI | LLM | TODO·일정 충돌·회의 요약의 검토 가능한 초안 |
| 데이터 | Supabase 등 후속 확정 | 사용자, TODO, 일정, 요청, 회의 기록 저장 |

## 9. 데모 성공 기준

1. 한국 측 PM이 큰 오피스에서 피플 목록으로 베트남 담당자를 찾는다.
2. 담당자의 공개 TODO와 가까운 휴가 일정을 확인해 일정 위험을 이해한다.
3. PM이 찾아가기 또는 호출 요청으로 대화를 시작한다.
4. 두 사용자가 회의실에서 한국어·베트남어 번역 자막을 확인한다.
5. 심사위원이 화면 공유·감시 없이도 협업의 불확실성을 낮추는 흐름을 이해한다.

| 리스크 | 대응 |
| --- | --- |
| TODO가 감시로 느껴짐 | 직접 작성·공개 범위 선택을 기본으로 하고, 활동 추적과 점수화를 금지한다. |
| 일정 정보가 과도하게 노출됨 | 휴가·재택·부재 등 협업 영향 정보만 공유하고, 사유·개인 일정은 수집하지 않는다. |
| 큰 맵에서 상호작용이 불편함 | 피플 목록·검색·찾아가기·호출 요청을 항상 제공한다. |
| 번역 지연 또는 실패 | 원문과 처리 상태를 먼저 표시하고, 데모 fallback을 준비한다. |
| 기능 범위 과다 | P0는 수동 TODO·수동 캘린더·핵심 회의 흐름에 집중하고 AI 자동화는 P1으로 둔다. |

## 11. 검증 질문

- 공개 TODO가 화면 공유 없이도 상대 작업의 맥락을 이해하는 데 도움이 되었는가?
- 공유 캘린더가 휴가·재택으로 인한 일정 공백을 미리 조정하는 데 도움이 되었는가?
- 피플 목록과 찾아가기 기능이 큰 맵에서 팀원에게 접근하는 시간을 줄였는가?
- 번역 자막이 한국어·베트남어 회의 참여와 이해를 높였는가?
