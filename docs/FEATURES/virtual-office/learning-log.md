## 목적

가상 오피스는 단순한 온라인 여부가 아니라, 팀원이 지금 협업 가능한지와 언제 업무를 다시 이어갈 수 있는지를 보여줘야 한다. 이 문서는 아바타를 서비스 연결과 분리해 유지하고, 출퇴근과 캘린더 일정을 신뢰 가능한 상태로 보여주기 위한 기준을 기록한다.

## 상태를 나누는 이유

브라우저 연결이 끊겼다는 사실만으로 퇴근했다고 판단할 수 없다. 네트워크 문제, 노트북 절전, 탭 종료처럼 사용자의 의도와 무관한 상황도 있기 때문이다.

따라서 한 명의 멤버 상태를 아래 세 축으로 나눈다.

| 상태 | 의미 | 대표 값 | 관리 주체 |
| --- | --- | --- | --- |
| 연결 상태 | 현재 Socket 연결 여부 | `connected`, `disconnected` | Socket 서버 |
| 출퇴근 상태 | 사용자가 명시적으로 업무를 시작하거나 종료했는지 | `working`, `checked_out` | 서버와 DB |
| 협업 가능 상태 | 다른 팀원이 연락하거나 협업할 수 있는지 | `available`, `focus`, `meeting`, `vacation`, `remote_work`, `absent` | 캘린더와 서버 |

예시:

- 출근하고 접속 중: `connected + working + available`
- 퇴근 버튼을 누른 뒤 종료: `disconnected + checked_out + available`
- 휴가 기간: `disconnected + checked_out + vacation`
- 브라우저가 예기치 않게 종료됨: `disconnected + working + available`

마지막 경우에는 `퇴근`으로 표시하지 않고 `연결 끊김`과 마지막 활동 시각을 보여준다.

## 영속 아바타와 고정 데스크

아바타는 Socket 세션에 귀속되지 않는다. `members`와 `desks`의 관계로 고정 데스크, 아바타 종류, 마지막 위치를 DB에 저장한다.

- 사용자가 퇴근하거나 탭을 닫아도 아바타 레코드와 데스크 배정은 삭제하지 않는다.
- 클라이언트는 상태에 따라 같은 아바타를 `active`, `sleeping`, `ghost`, `vacation`으로 다르게 표현한다.
- 다시 접속하면 `guest_token`으로 기존 멤버를 찾고, 저장한 위치와 데스크에서 활성 상태로 복구한다.
- 퇴근한 멤버의 데스크를 클릭하면 퇴근 시각 또는 다음 근무 가능 정보를 확인할 수 있다.

이 방식은 오프라인 팀원을 NPC처럼 남겨 두려는 목적이 아니라, 누가 어느 데스크를 사용하며 현재 어떤 협업 상태인지 공간 안에서 확인하게 하기 위한 것이다.

## 연결 종료와 재접속 처리

### 접속 중

1. 클라이언트가 Socket에 연결한다.
2. 서버는 `connection_status`를 `connected`로 바꾸고 `last_heartbeat_at`을 갱신한다.
3. 이동 위치는 Socket 이벤트로 우선 동기화한다.
4. 이동 종료, 출퇴근, 상태 변경 등 의미 있는 시점에만 마지막 위치와 상태를 DB에 저장한다.

### 정상 퇴근

1. 사용자가 `퇴근하기`를 누른다.
2. 서버는 `attendance_status = checked_out`, `checked_out_at`을 저장한다.
3. 전체 클라이언트에 상태 변경을 전파한다.
4. 화면은 아바타를 데스크에 남긴 채 잠자는 상태 또는 채도가 낮은 상태로 전환한다.

### 비정상 종료 또는 네트워크 단절

1. Socket `disconnect` 이벤트가 오면 `connection_status = disconnected`를 기록한다.
2. 이벤트를 받지 못한 경우에도 `last_heartbeat_at`이 60~90초 이상 갱신되지 않으면 연결 해제로 판단한다.
3. 출퇴근 상태는 기존 값을 유지한다. 연결 해제만으로 퇴근 기록을 만들지 않는다.
4. 다시 연결하면 같은 `guest_token`의 멤버와 데스크를 복구하고, 연결 상태만 `connected`로 바꾼다.

## 캘린더가 상태 UI에 반영되는 방식

공유 캘린더에는 휴가, 재택, 부재, 회의, 집중 시간을 저장한다. 현재 시각에 유효한 일정이 있으면 서버 또는 클라이언트가 이를 우선 반영한다.

| 일정 종류 | 협업 가능 상태 | 아바타 표현 예시 |
| --- | --- | --- |
| 휴가 | `vacation` | 휴가 말풍선, 낮은 채도 |
| 재택 | `remote_work` | 재택 말풍선, 원격 데스크 표현 |
| 부재 | `absent` | 부재 말풍선 |
| 회의 | `meeting` | 회의실 이동 또는 회의 배지 |
| 집중 시간 | `focus` | 방해 금지 배지 |

명시적으로 휴가 상태를 입력하지 않아도, 현재 유효한 캘린더 일정으로 UI 상태를 계산할 수 있다. 다만 사용자가 직접 설정한 상태와 일정이 충돌할 때의 우선순위는 구현 전에 별도 계약으로 확정한다.

## DB와 Socket의 책임 경계

| 데이터 | DB | Socket |
| --- | --- | --- |
| 멤버, 아바타, 고정 데스크 | 저장 | 읽기 및 변경 알림 |
| 출근·퇴근 기록 | 저장 | 즉시 전파 |
| 캘린더 일정과 TODO | 저장 | 변경 시 전파 |
| 현재 이동 좌표 | 마지막 위치만 저장 | 실시간 동기화 |
| 연결 상태와 heartbeat | 마지막 시각 저장 | 연결·이탈 감지 |

이동 이벤트를 매번 DB에 쓰지 않는다. 다중 사용자가 이동할 때 불필요한 쓰기 요청이 늘어나므로, 실시간 위치는 Socket으로 처리하고 마지막 위치만 저장한다.

## Supabase ERD 반영 항목

아래 엔티티를 사용한다.

- `workspaces`: 하나의 협업 공간
- `members`: 게스트 토큰 기반 팀원과 아바타 정보
- `desks`: 맵 안의 고정 데스크와 배정 멤버
- `member_presence`: 연결, 출퇴근, 협업 가능 상태와 마지막 위치
- `attendance_logs`: 출근, 퇴근, 연결 해제 기록
- `todos`: 팀원이 공개할 수 있는 오늘의 할 일
- `calendar_events`, `calendar_event_participants`: 공유 일정과 대상자
- `meeting_rooms`, `meeting_participants`: LiveKit 회의 방과 참석 이력

## 주의할 점

- 게스트 토큰은 로그인 대체 식별자일 뿐이다. 실제 서비스의 권한 제어 방식은 별도로 설계해야 한다.
- `guest_token`을 클라이언트에서 단순 문자열로만 신뢰하면 다른 사용자가 위조할 수 있다. 해커톤 MVP에서는 편의성을 우선하되, 실사용에서는 서명된 세션 또는 인증으로 교체해야 한다.
- 휴가·재택 여부는 개인 일정이므로 실제 서비스로 확장할 때는 공개 범위와 동의 정책이 필요하다.
- `updated_at` 자동 갱신 트리거와 상태 우선순위는 API·Socket 계약이 확정될 때 추가한다.
