# 신규 게스트 gray-cat 아바타 프리뷰

## 목적

새 브라우저 프로필로 생성하는 게스트가 `gray-cat` 아바타를 받아, 로컬과 원격 화면에서 계정별 아바타 렌더링을 검증할 수 있게 한다. 기존에 생성한 게스트의 `members.avatar_id`는 수정하지 않는다.

## 동작 범위

| 구분 | 기존 게스트 | 신규 게스트 |
| --- | --- | --- |
| 저장된 `avatar_id` | 기존 `office-avatar-*` 값 유지 | `gray-cat` |
| 스프라이트 | `image.png`의 6 x 4, 256px 프레임 | `gray-cat.webp` 상단 4개 정지 포즈 |
| 정지 | 방향별 idle 프레임 | 방향별 정지 포즈 |
| 이동 | 기존 6프레임 보행 애니메이션 | 방향 전환만 적용, 보행 프레임 미적용 |

`avatar_id`는 세션 응답뿐 아니라 Socket의 `OfficeMemberPresence`에도 포함한다. 따라서 다른 브라우저에서도 같은 아바타 정의를 선택한다.

## gray-cat 원본 매핑

현재 원본은 `1619 x 971` 크기의 비표준 아틀라스다. 표준 시트처럼 보행 순서와 프레임 경계가 확정되지 않았으므로, 상단의 검증된 정지 포즈만 사용한다.

| 방향 | 원본 crop |
| --- | --- |
| 아래 | `x: 56, y: 32, 128 x 128` |
| 위 | `x: 184, y: 32, 128 x 128` |
| 왼쪽 | `x: 312, y: 32, 128 x 128` |
| 오른쪽 | `x: 440, y: 32, 128 x 128` |

Phaser는 crop을 화면에 직접 쓰지 않고, 각 포즈의 투명 여백을 제거해 발 기준선에 맞춘 임시 캔버스 프레임을 만든다. 이 방식은 맵 좌표와 label 위치를 기존 아바타와 같은 기준으로 유지한다.

## 수동 검증 절차

1. 일반 창에서 기존 `guestToken`으로 입장한다.
2. 시크릿 창 또는 다른 브라우저 프로필에서 이름과 국가를 입력해 새 게스트를 생성한다.
3. 새 게스트가 gray-cat으로 보이고, 기존 게스트가 기존 보행 아바타로 남아 있는지 확인한다.
4. 새 게스트를 상하좌우로 이동한다.
5. 기존 창에서 gray-cat의 위치와 방향이 실시간으로 반영되는지 확인한다.
6. 새 게스트를 새로고침해도 `gray-cat`이 유지되는지 확인한다.

## 검증 결과

- 2026-08-17 로컬 Nest 서버(`:4001`)에서 신규 세션을 생성해 응답의 `member.avatarId === "gray-cat"`을 확인했다.
- 로컬 Vite 클라이언트의 `/office` 응답과 서버 `/health` 응답은 모두 HTTP 200을 확인했다.
- 브라우저 시각 확인은 새 게스트가 배정된 상태에서 위 수동 절차로 이어서 진행한다.

## 다음 에셋 작업

gray-cat 보행까지 적용하려면 디자이너가 아래 규격의 별도 파일을 제공해야 한다.

- PNG, 투명 배경, `1536 x 1024`
- `256 x 256` 프레임 24개, `6열 x 4행`
- 1행: idle `아래, 위, 좌, 우`를 포함
- 2행: 아래 보행 6프레임
- 3행: 위 보행 6프레임
- 4행: 좌 또는 우 보행 6프레임. 반대쪽은 수평 반전으로 사용
- 각 프레임은 캐릭터 발 위치와 투명 여백 기준을 통일

새 표준 시트가 들어오면 `avatar-sprite-definition.ts`의 gray-cat 정의만 표준 프레임 목록으로 교체한다. 서버와 Socket 계약은 바꾸지 않는다.
