# Socket.IO와 실시간 Presence

## 1. Presence란 무엇인가

Presence는 같은 서비스에 누가 접속해 있는지, 어디에 있는지, 현재 어떤 상태인지 알려 주는 기능이다. Virtual Office에서는 팀원의 아바타 위치와 `협업 가능`, `집중 작업`, `회의 중`, `자리 비움` 상태가 Presence에 해당한다.

## 2. 우리 서비스에서 필요한 문제

- 팀원이 입장하거나 나가면 오피스 화면이 바로 갱신되어야 한다.
- 아바타 이동과 상태 변경이 다른 사용자에게 빠르게 전달되어야 한다.
- 새로 접속한 사용자는 현재 오피스의 팀원 상태를 한 번에 받아야 한다.
- 네트워크가 끊겼다가 복구돼도 오래된 아바타가 남지 않아야 한다.

## 3. 대안 비교

| 방법 | 장점 | 한계 | Virtual Office 적합성 |
| --- | --- | --- | --- |
| HTTP Polling | 구현이 단순하다 | 반복 요청으로 지연과 불필요한 통신이 생긴다 | 낮음 |
| Server-Sent Events | 서버에서 Client로 알림을 보내기 쉽다 | Client가 서버로 이동 데이터를 보내기에는 별도 HTTP 요청이 필요하다 | 중간 |
| 순수 WebSocket | 표준 기술이고 세밀하게 제어할 수 있다 | 재연결, 룸, 이벤트 규약을 직접 구현해야 한다 | 중간 |
| Socket.IO | 양방향 이벤트, 룸, 재연결 지원을 제공한다 | 이벤트 이름과 상태 기준을 엄격히 관리해야 한다 | 높음 |

## 4. Socket.IO를 채택했을 때의 장점

- 이동, 입장, 퇴장, 상태 변경을 이벤트로 명확하게 나눌 수 있다.
- 한 팀 오피스에 속한 사용자에게만 이벤트를 보낼 수 있다.
- 연결이 끊긴 뒤 재연결하는 기본 기능을 활용할 수 있다.
- NestJS Server와 React Client에서 사용하기 쉬운 형태로 제공된다.

## 5. 중요한 설계 원칙

- Socket 연결은 앱 전체에서 하나만 만든다.
- 서버는 인증된 사용자와 현재 오피스를 기준으로 이벤트를 중계한다.
- 화면은 `memberId`로 팀원을 식별한다. 연결마다 바뀔 수 있는 Socket ID를 사용자 식별자로 쓰지 않는다.
- 이동은 매 화면 프레임이 아니라, 실제 변화가 있을 때 제한된 빈도로 전송한다.
- 새로 접속하거나 재접속하면 현재 상태 전체를 다시 받는다.

## 6. 우리 서비스의 채택 제안

Socket.IO를 팀원 Presence 동기화에 사용한다. 초기 MVP는 데이터베이스 없이 Server 메모리에 접속 상태를 두고, 데모 규모에서 입장·퇴장·이동·상태 변경을 검증한다.

이 선택은 아직 팀 합의 전의 제안이다. 합의 뒤에는 이벤트 이름, 권한 검증, 재접속 처리 기준을 ADR에 기록한다.

## 7. 구현 전 확인할 질문

- 개발용 사용자를 어떤 방식으로 구분할 것인가?
- 이동 이벤트의 전송 빈도와 좌표 범위는 어떻게 제한할 것인가?
- 상태 변경에 한 줄 작업 맥락과 응답 가능 시간을 함께 포함할 것인가?
- 재접속한 사용자의 이전 상태를 어디까지 복구할 것인가?
