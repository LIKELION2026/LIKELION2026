# Phaser와 2D 가상 오피스

## 1. Phaser란 무엇인가

Phaser는 브라우저에서 2D 게임 화면을 만들기 위한 JavaScript 프레임워크다. 화면을 장면(Scene) 단위로 나누고, Sprite, 키보드 입력, 카메라, 충돌, 애니메이션을 제공한다.

Virtual Office에서는 게임을 만드는 것이 목적이 아니라, 여러 사람이 같은 공간을 이동하는 경험을 안정적으로 표현하는 것이 목적이다.

## 2. 우리 서비스에서 필요한 문제

- 픽셀 아바타가 키보드로 자연스럽게 이동해야 한다.
- 벽과 가구를 통과하지 않아야 한다.
- 다른 팀원의 아바타, 이름, 상태가 같은 공간에 보여야 한다.
- 회의실·라운지처럼 특정 위치에서 다른 행동을 시작할 수 있어야 한다.

## 3. 대안 비교

| 방법 | 장점 | 한계 | Virtual Office 적합성 |
| --- | --- | --- | --- |
| 일반 React DOM | 정보 패널과 폼 구현이 편하다 | 다수 Sprite 이동·충돌·카메라를 직접 구현해야 한다 | 낮음 |
| CSS 배경 이미지 + 절대 위치 | 빠른 화면 시연에 적합하다 | 충돌, 카메라, 맵 상호작용이 커질수록 유지가 어렵다 | 낮음 |
| Three.js | 3D 공간과 조명 표현에 강하다 | 2D 픽셀 오피스에는 학습·에셋·성능 부담이 크다 | 낮음 |
| Phaser | 2D Sprite, 입력, 카메라, 충돌, 타일 맵 기능이 준비되어 있다 | 게임 루프와 React UI의 책임을 분리해야 한다 | 높음 |

## 4. Phaser를 채택했을 때의 장점

- 아바타 이동과 애니메이션을 화면 프레임 단위로 처리할 수 있다.
- 벽·가구 충돌과 카메라 추적을 기본 기능으로 구현할 수 있다.
- 타일 맵을 불러와 회의실·라운지 같은 공간을 확장하기 쉽다.
- 일반 웹 UI는 React로 유지해, 상태 패널과 회의 화면을 익숙한 방식으로 만들 수 있다.

## 5. 주의할 점

- Phaser Scene 안에 API 요청, 인증, 회의 연결 같은 서비스 로직을 넣지 않는다.
- React의 상태 변경마다 게임을 다시 만들지 않는다.
- Canvas 위 UI와 일반 웹 UI의 클릭·키보드 입력이 겹치지 않게 관리해야 한다.
- 픽셀 아트는 원본 타일 크기와 아바타 프레임 크기를 시작 전에 고정해야 한다.

## 6. 우리 서비스의 채택 제안

Phaser는 2D 오피스의 맵, 아바타 이동, 충돌, 카메라, 원격 아바타 표시를 담당한다. 팀원 상세 정보, 상태 변경, 화상회의, 번역 자막은 일반 웹 UI로 만든다.

이 선택은 아직 팀 합의 전의 제안이다. 합의 후 ADR에는 “Phaser를 선택한 이유와 Three.js·일반 DOM을 선택하지 않은 이유”를 짧게 기록한다.

## 7. 구현 전 확인할 질문

- 첫 데모에서 필요한 동시 접속자 수는 몇 명인가?
- 아바타와 타일의 원본 픽셀 크기를 `16px` 기준으로 확정할 수 있는가?
- 데스크톱 우선 화면에서 카메라 확대 비율은 어느 정도가 적절한가?
- 회의 전체화면이 열릴 때 오피스 조작을 어떻게 중지할 것인가?
