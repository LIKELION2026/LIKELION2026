# LiveKit 회의와 오피스 화면의 경계

## 1. LiveKit은 무엇인가

LiveKit은 브라우저에서 영상·음성·데이터를 실시간으로 주고받는 기능을 만들기 위한 실시간 미디어 플랫폼이다. 회의방 연결, 참가자, 카메라·마이크 트랙 같은 기능을 제공한다.

## 2. 우리 서비스에서 필요한 문제

- 사용자가 오피스에서 자연스럽게 회의를 시작할 수 있어야 한다.
- 카메라·마이크 권한은 사용자가 원할 때만 요청해야 한다.
- 회의 화면과 번역 자막은 오피스 이동 화면과 다른 방식으로 동작한다.
- 화상회의 담당자가 오피스 담당자의 작업을 기다리지 않고 개발할 수 있어야 한다.

## 3. 대안 비교

| 방법 | 장점 | 한계 | Virtual Office 적합성 |
| --- | --- | --- | --- |
| 브라우저 WebRTC 직접 구현 | 미디어 연결을 세밀하게 제어할 수 있다 | 신호 교환, 참가자 관리, 네트워크 대응 부담이 크다 | 낮음 |
| 화상회의 링크 외부 이동 | 구현이 빠르다 | 오피스 경험과 번역 자막을 서비스 안에서 연결하기 어렵다 | 중간 |
| LiveKit | 회의방, 참가자, 미디어 트랙을 빠르게 연결할 수 있다 | 토큰 발급과 권한 관리를 Server에서 설계해야 한다 | 높음 |

## 4. LiveKit을 채택했을 때의 장점

- 회의 기능을 오피스 이동 기능과 독립적으로 개발할 수 있다.
- 회의 화면, 기기 권한, 연결 오류, 자막 UI를 별도 기능으로 검증할 수 있다.
- 오피스 담당자는 회의실 진입과 참여 안내까지만 구현하면 된다.
- 회의가 끝나면 사용자는 같은 오피스 화면으로 돌아올 수 있다.

## 5. 경계를 나누는 이유

오피스 화면은 “누가 어디에 있고, 지금 회의할 수 있는가”를 보여 준다. 회의 기능은 “영상·음성·자막을 어떻게 연결하고 표시하는가”를 담당한다.

따라서 회의실에 들어가는 것과 실제 회의에 참여하는 것은 다르다. 회의실 영역에 들어가면 참여 안내를 보여 주고, 사용자가 참여를 누른 뒤에만 카메라·마이크를 연결한다.

## 6. 우리 서비스의 채택 제안

LiveKit은 별도 회의 기능으로 만든다. 오피스 화면은 회의실 이름과 참여 동작을 전달하고, 회의 기능은 권한 확인과 실제 연결을 담당한다. 회의 중 여부만 오피스의 아바타 상태에 반영한다.

이 선택은 아직 팀 합의 전의 제안이다. 합의 뒤에는 토큰 발급 권한, 회의방 이름 규칙, 오피스와 회의의 연결 책임을 ADR에 기록한다.

## 7. 구현 전 확인할 질문

- 회의는 1:1만 지원할지, 소규모 회의실까지 지원할지?
- 회의실 이름은 고정 이름을 사용할지, 팀·시간 기준으로 만들지?
- 번역 자막은 실제 음성 인식으로 연결할지, 데모용 이벤트를 먼저 검증할지?
- 회의 종료 뒤 아바타 상태와 카메라·마이크 상태를 어떻게 정리할지?
