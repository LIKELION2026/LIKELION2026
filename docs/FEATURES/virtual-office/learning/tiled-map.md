# Tiled와 픽셀 오피스 맵

## 1. Tiled란 무엇인가

Tiled는 타일 기반 2D 맵을 만드는 편집 도구다. 작은 타일을 조합해 바닥, 벽, 가구가 있는 공간을 만들고, 보이지 않는 충돌 영역과 상호작용 영역도 함께 표시할 수 있다.

## 2. 우리 서비스에서 필요한 문제

- 디자인 팀이 만든 오피스를 개발 화면에 반복해서 수정·적용할 수 있어야 한다.
- 보이는 가구와 실제로 지나갈 수 없는 영역을 구분해야 한다.
- 회의실, 라운지, 책상처럼 공간마다 다른 행동을 연결해야 한다.
- 아바타와 가구의 크기·깊이 관계가 어색하지 않아야 한다.

## 3. 대안 비교

| 방법 | 장점 | 한계 | Virtual Office 적합성 |
| --- | --- | --- | --- |
| 한 장의 배경 이미지 | 가장 빠르게 시각 시안을 만들 수 있다 | 충돌·공간 상호작용·부분 수정이 어렵다 | 낮음 |
| 코드로 좌표와 가구를 직접 배치 | 개발자가 모든 동작을 제어할 수 있다 | 디자이너 수정마다 코드 변경이 필요하다 | 중간 |
| Tiled 타일 맵 | 공간 디자인과 충돌·상호작용 정보를 함께 관리할 수 있다 | 타일 크기와 레이어 규칙을 팀이 맞춰야 한다 | 높음 |

## 4. Tiled를 채택했을 때의 장점

- 바닥·벽·가구를 조합해 오피스 배치를 빠르게 바꿀 수 있다.
- 디자인 정보와 이동 가능 영역을 분리해 관리할 수 있다.
- 회의실 같은 공간에 보이지 않는 상호작용 영역을 지정할 수 있다.
- 새 공간을 추가할 때 기존 게임 코드를 크게 바꾸지 않아도 된다.

## 5. 디자인과 개발이 함께 지켜야 할 기준

- MVP는 `16 x 16px` 타일과 `16 x 32px` 아바타 프레임을 기준으로 시작한다.
- 벽과 큰 가구의 보이는 모습, 통과 불가 영역, 회의실 영역은 서로 구분해 전달한다.
- 회의실·라운지·책상은 처음 보는 사용자가 용도를 짐작할 수 있도록 시각적으로 구분한다.
- 맵의 타일 크기를 중간에 바꾸면 가구와 아바타를 함께 다시 맞춰야 한다.

## 6. 우리 서비스의 채택 제안

초기에는 임시 도형으로 공간 구조와 아바타 이동을 검증한다. 디자인 에셋이 준비되면 Tiled 맵으로 교체해 공간의 시각적 완성도와 상호작용 영역을 함께 관리한다.

이 선택은 아직 팀 합의 전의 제안이다. 합의 뒤에는 맵 파일 형식, 타일 크기, 디자인 전달 규칙을 ADR에 기록한다.

## 7. 구현 전 확인할 질문

- 오피스 맵의 최초 크기와 화면에서 보일 범위는 어느 정도인가?
- 회의실·라운지·책상 중 MVP에서 실제 상호작용이 필요한 공간은 무엇인가?
- 디자인 팀은 Tiled를 직접 사용할 수 있는가, 아니면 에셋과 배치 시안만 전달할 것인가?
- 타일셋의 라이선스와 출처를 어떻게 기록할 것인가?
