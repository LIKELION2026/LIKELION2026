# TODO User Scenarios

> 관련 Issue: #52
> 관련 계약: [Public TODO Contract](./public-todos.md)
> UI 연결 기준: [TODO UI Shell](./todo-ui-shell.md)
> 전체 서비스 흐름: [Virtual Office User Scenarios](./user-scenarios.md)

## 시나리오 목표

서로 다른 공간에서 일하는 한국·베트남 팀원이 화면이나 활동량을 감시하지 않고도, 오늘 진행 중인 업무와 도움이 필요한 지점을 확인한다.

## 공통 원칙

- 사용자가 직접 작성하거나 수정한 TODO만 공유한다.
- 타인은 공개 TODO만 읽을 수 있고, 다른 사람의 TODO를 수정할 수 없다.
- `도움 필요(blocked)`는 업무 평가나 감시 신호가 아니라 도움·일정 조정 요청이다.
- TODO가 없거나 공개하지 않아도 부정적인 상태로 표현하지 않는다.

## 시나리오 1. 입장 후 오늘의 업무를 공유한다

**사용자:** 한국 팀 프론트엔드 개발자 민지
**목표:** 일을 시작했다는 사실과 오늘의 협업 맥락을 팀에 자발적으로 남긴다.

1. 민지는 이름과 국가를 선택해 가상 오피스에 입장한다.
2. 자신의 아바타 또는 데스크를 선택해 **내 업무 패널**을 연다.
3. 오늘 할 일인 `회의 번역 자막 UI 연결`을 입력하고 공개 범위를 팀 공개로 둔다.
4. 작업을 시작하면서 상태를 `진행 중`으로 바꾼다.
5. 다른 팀원이 확인할 수 있도록 해당 TODO가 공개 목록에 반영된다.

**사용자가 확인하는 결과**

- 내 TODO에는 생성·수정·상태 변경·공개 범위 변경이 가능하다.
- 저장 후 내 목록과 팀 공개 목록이 다시 조회된다.
- TODO 제목에 `W`, `A`, `S`, `D` 또는 방향키를 입력해도 오피스 아바타는 이동하지 않는다.

**현재 구현 상태**

- 내 TODO 패널에서 제목 작성, 팀 공개 여부 선택, 상태·공개 여부 변경 구현 완료
- 저장 뒤 내 TODO와 팀 공개 TODO를 다시 조회한다.
- 동일 workspace의 다른 입장자는 TODO 변경 Socket 이벤트를 받아 공개 TODO를 다시 조회한다.
- 아바타·데스크 클릭으로 내 업무 패널을 여는 연결은 후속 범위

### 입력과 이동의 경계

- `input`, `textarea`, `select`, `contenteditable` 요소에 포커스가 있으면 Phaser 이동 입력을 처리하지 않는다.
- 해당 포커스가 해제되면 기존 `WASD`와 방향키 이동을 다시 사용한다.
- Phaser의 전역 키 capture를 끄므로 텍스트 입력 요소가 브라우저 기본 키 입력을 정상 수신한다.

## 시나리오 2. 팀원의 작업 맥락을 확인한다

**사용자:** 베트남 팀 백엔드 개발자 An
**목표:** 민지에게 반복해서 메시지를 보내지 않고 현재 협업 맥락을 파악한다.

1. An은 People 목록에서 민지를 찾거나 오피스 내 민지의 아바타를 선택한다.
2. **타인 프로필 패널**에서 민지의 현재 협업 상태와 공개 TODO를 확인한다.
3. `회의 번역 자막 UI 연결 · 진행 중`을 보고, 자신이 담당한 API 응답 필드 확인 작업을 계속한다.
4. 추가 확인이 필요할 때만 메시지 또는 회의 요청을 선택한다.

**사용자가 확인하는 결과**

- 타인 패널에는 공개 TODO만 표시된다.
- 비공개 TODO와 입력·수정 버튼은 타인에게 보이지 않는다.

**현재 구현 상태**

- 공개 TODO 조회 API와 controller 준비 완료
- People 목록에서 팀원 선택, 읽기 전용 프로필의 공개 TODO 확인, `찾아가기` 카메라 이동 구현 완료
- 다른 팀원이 TODO를 저장하면 Socket 이벤트로 공개 TODO 목록을 다시 조회한다.
- 메시지·회의 요청과 낙관적 갱신은 후속 범위

## 시나리오 3. 막힌 일을 도움 요청으로 전환한다

**사용자:** 민지
**목표:** 지연 사실을 숨기거나 개인 평가처럼 보이게 하지 않고, 팀의 도움을 요청한다.

1. 민지는 번역 자막 UI 연결 중 API 응답 규격이 확정되지 않았음을 확인한다.
2. 자신의 TODO 상태를 `도움 필요`로 변경하고 제목을 `번역 자막 UI 연결 - API 응답 확인 필요`로 보완한다.
3. An은 공개 TODO에서 도움 요청을 확인한다.
4. An은 필요한 응답 필드를 공유하거나 짧은 회의를 제안한다.
5. 민지는 해결 후 상태를 `진행 중` 또는 `완료`로 바꾼다.

**사용자가 확인하는 결과**

- `도움 필요`는 빨간 경고나 실패 판정이 아닌 협업 상태로 표시한다.
- 후속 디자인에서는 상태 라벨과 짧은 설명으로 의미를 전달한다.

**현재 구현 상태**

- `blocked` 상태 저장·수정 API 준비 완료
- `blocked`를 포함한 상태 변경 뒤 같은 workspace의 공개 TODO가 Socket 이벤트로 갱신된다.
- 낙관적 갱신은 후속 범위

## 패널별 데이터와 권한

| 패널 | 데이터 | 행동 | 권한 |
| --- | --- | --- | --- |
| 내 업무 패널 | 내 TODO 전체 | 생성, 상태 변경, 공개 범위 변경 | 본인 guest token |
| 타인 프로필 패널 | 해당 팀원의 공개 TODO | 읽기, 찾아가기 | 워크스페이스 공개 조회 |
| People 목록 | 팀원 이름, 상태 | 팀원 선택, 찾아가기 | Socket snapshot |

## 디자인 검토가 필요한 결정

1. 내 업무 패널과 타인 프로필 패널을 한 패널의 권한별 변형으로 만들지, 별도 컴포넌트로 만들지
2. TODO 상태 4종의 이름과 색상 체계
3. 공개 여부를 각 TODO에서 바꾸는 방식과 기본 공개값
4. 도움 필요 상태를 어떤 문구와 아이콘으로 중립적으로 표현할지
